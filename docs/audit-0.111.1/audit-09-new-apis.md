## 潜在 Bug / 行为差异（mod 逻辑 vs 0.111.1 语义）

1. **0.111.1 多人大厅重构（已见于前序审计）**：`StartRunLobby`/`LoadRunLobby`/`RunLobby` 拆分 + `HandshakeManager`/`HandshakeResult`/`HandshakeStatus`/`IHandshakeHandler` 新增（`Core/Multiplayer/Connection/*`，0.111.1 新增 4 文件），`ClientConnectionFailedMessage` 删除（0.110.1→0.111.1 文件差异 -1），`RunLobbyPlayer.isModded`/`PeerVersionInfo`（`Core/Multiplayer/PeerVersionInfo.cs:18-140`）承载 mod 名单与 `idDatabaseHash` 握手校验。Jaina 是纯本地单人角色 mod，不触碰大厅/握手 API，无运行期影响；但 `ModManager.GetGameplayRelevantModNameList`（ModManager.cs:985）会按 `affectsGameplay: true`（jaina.json 已声明）把 Jaina 列入 mod 名单——多人房间内 mod 不一致会被 0.111.1 的握手正确拒绝（`HandshakeStatus.ModMismatch`），属预期行为，无需处理。
2. **0.111.1 回合循环加固（CombatManager.cs 大改）**：新增 `StuckCombatException`（`Core/Combat/StuckCombatException.cs`，0.111.1 新增文件）、`IsCurrentLiveCombat(CombatId?)`（CombatManager.cs:358，0.110.1 无此 API）、`EndCombatInternal`/`EndPlayerTurnPhaseOneInternal`/`EndPlayerTurnPhaseTwoInternal`/`SwitchFromPlayerToEnemySide` 由 public 改 internal/private（0.110.1 为 public，0.111.1 收窄，CombatManager.cs:1291/1509/1732/1820）。**Jaina/MinionLib/RitsuLib 均未引用这四个收窄方法**（已全文检索），无断链；但收窄意味着任何依赖它们的第三方 mod 会编译失败，且"过期玩家回合结束信号"在 0.111.1 由"丢弃"改为"照跑 + Sentry 上报"（CombatManager.cs:1446-1459）——Jaina 的 `BeforeSideTurnEnd` 随从自动攻击（JainaMinionBase.cs:356-378）挂在 Hook 上，语义不变，但若未来出现回合结束钩子竞态，0.111.1 会记录 Sentry 而非静默丢弃。
3. **`CardModel.OnTurnEndInHandWrapper` 重构（CardModel.cs:1686-1689）**：0.111.1 把"手牌回合结束效果"统一搬进 `CombatManager.DoTurnEndCards`（CombatManager.cs:1636-1689，含延迟/Play 堆过渡/结果堆/Ethereal 分支），`OnTurnEndInHandWrapper` 简化为直调 `OnTurnEndInHand`；`HasTurnEndInHandEffect` 门控（CardModel.cs:1044）与 `CardKeyword.Retain`/`ShouldRetainThisTurn`（CardModel.cs:591）语义未变。Jaina 无 OnTurnEndInHand 类卡，无影响；若未来做"回合结束手牌效果"卡，按新语义实现即可（改进机会 6）。
4. **`Rng.NextUnsignedLong` 默认参数变化**：0.110.1 `NextUnsignedLong(ulong maxExclusive)` → 0.111.1 `NextUnsignedLong(ulong maxExclusive = ulong.MaxValue)`（Rng.cs:140），纯增量；`CardPile.InvokeCardRemoved` 由内联调用改为公开方法（CardPile.cs，0.111.1 新增 public 方法），无行为差异。Jaina 只用 `NextInt`/`NextFloat`/`NextItem`（JainaMinionPool.cs:63/168、JainaMinionBase.cs:406、FlameWardPower.cs:49 等），签名未变。
5. **`CreatureCmd.Heal` 微调（CreatureCmd.cs:738-810）**：0.111.1 增加 `wasDead` 判定与复活动画（`StartReviveAnim`，:772-775）、玩家 Idle 动画重播（:766-769）；签名不变。Jaina 无直接 Heal 调用（ArcaneArtificer 用 GainBlock，IceBarrier 用 GainBlock），无影响；若未来做治疗随从，0.111.1 的 Heal 会正确处理"从死亡复活"。
6. **意图显示链路在 0.111.1 无新 API 变化**：`NIntent.UpdateVisuals` 数值标签分支仍只认 `AttackIntent`/`StatusIntent` 实例（NIntent.cs:135），`JainaConditionalAttackIntent`（非 AttackIntent 子类）的数值标签仍不渲染——audit-01 中 1 结论在 0.111.1 保持不变；`NCreature.UpdateIntent` 多意图渲染（NCreature.cs:290-311）与 `MonsterModel.IntendsToAttack`（MonsterModel.cs:242-246）未变。
7. **冻结无官方机制**：0.111.1 无冻结 Power（`Freeze` 相关仅 UI 层 `NIntent.SetFrozen` 意图冻结动画，NIntent.cs:166-169，与 Jaina 的伤害冻结语义无关）；Jaina 的 `FreezePower` 自建减伤实现仍是唯一途径，audit-02 中 1（`IsPoweredAttack` 守卫 + 随从 `Unpowered` 结算导致冻结对随从攻击无效）在 0.111.1 继续成立，需按 audit-02 建议修复。
8. **压轴（Finisher）无官方关键词**：0.111.1 `CardKeyword` 枚举仍仅 8 成员（None/Exhaust/Ethereal/Innate/Unplayable/Retain/Sly/Eternal，CardKeyword.cs:18-28），无 Finisher；`Finisher` 仅是 SilentCardPool 中的一张卡名（`Core/Models/Cards/Finisher.cs`，与 Jaina 的压轴语义无关）。压轴判断的官方钩子 `Hook.AfterEnergySpent`（Hook.cs:532）与 `CardPlay.Resources.EnergySpent`（CardPlay.cs:39）在 0.111.1 均在位，audit-02 中 2 的修复建议继续有效。

## 结论摘要

1. 0.111.1 相对 0.110.1 的实质变化集中在四处：多人大厅/握手重构（HandshakeManager 等 4 新文件 + 删除 ClientConnectionFailedMessage）、CombatManager 回合循环加固（StuckCombatException/IsCurrentLiveCombat + 4 方法 public→internal 收窄）、角色动画（GenerateAnimator 签名变化 + 低血量系统）、以及 CardModel 手牌回合结束效果调度重构；版本号无源码常量，来自运行时 ReleaseInfo（ReleaseInfoManager.cs:33-40、NGame.cs:1092）。
2. 对 Jaina 的兼容性影响为零高危：mod 未引用任何被收窄/改签名的 API；唯一中危是 RitsuLib 0.5.11 按 0.110.0 编译，`GenerateAnimator` 签名变化需在升级后冒烟（Jaina 自身不覆写，无改动）。
3. 最有价值的 0.111.1 可用改进：`CombatManager.IsCurrentLiveCombat` 统一收口 fire-and-forget 异步路径；`SetMoveImmediate` 官方化意图切换；`Hook.AfterEnergySpent` 精确化压轴；官方死亡清理链（`AfterDeath` + `ShouldCreatureBeRemovedFromCombatAfterDeath` + `OnPetDied`）支撑 audit-06 的亡语修复。
4. 商店/目标/压轴/冻结四块均无官方新机制：商店需保持类型替换 Prefix（官方稀有度钩子不能根治零候选）；AnyCreature 目标类型仍需 MinionLib；压轴无官方关键词（用 AfterEnergySpent）；冻结无官方 Power（保持自建 FreezePower）。
5. 总体：Jaina 可在 0.111.1 安全运行；建议优先落地 IsCurrentLiveCombat 异步保护、AfterEnergySpent 压轴、AfterDeath 亡语三处，并在升级 RitsuLib 后对角色动画与商店做冒烟回归。
